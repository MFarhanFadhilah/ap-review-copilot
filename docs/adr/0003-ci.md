# 3. Continuous integration

**Status:** accepted

## Context

The repo is public, so every push should prove three things: the code passes its tests, the committed sample is what the generator makes, and nothing private slipped in. The whole run should stay under about 5 minutes.

## Decision

One GitHub Actions job on Python 3.11 (`.github/workflows/ci.yml`), on every push and pull request:

1. Install from `requirements-lock.txt`, which pins exact versions.
2. `ruff check .`
3. Regenerate the sample and compare it byte for byte with the committed file and its near-duplicate ground truth.
4. `python -m ml.split`, `python -m ml.train`, `python -m ml.evaluate`
5. `pytest`, with an empty `ANTHROPIC_API_KEY`, so the agent runs offline.
6. `tools/check_public_safe.py` without private data: file size, `.xls` files and old-scheme tokens. The denylist is git-ignored, so CI has none. The check against the private file runs only on the owner's machine.

## Alternatives

- **Commit the model and skip training.** It saves about 10 seconds, at the cost of a stale binary in git.
- **A test matrix** across Python versions and operating systems. More coverage, but it multiplies the run time. The determinism check would also need one committed sample per platform if floating-point results differ.
- **Skip the determinism check.** It is the only thing that proves the committed sample matches the generator.

## Consequences

- A change to the generator or its config must come with a regenerated sample, or CI fails. That is intended.
- The determinism check depends on the pinned NumPy version, because NumPy does not promise the same random stream across versions. Upgrading NumPy may need a regenerated sample.
- The sample was generated on macOS. It has not yet been checked against a Linux run. If the bytes differ there (for example in the last digit of a log or exp result), CI will say so on its first run.
